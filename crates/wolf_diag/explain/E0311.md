# E0311: type arguments without a dot in an expression

In an expression, `name<Type>(...)` would read as two comparisons. Explicit type arguments of a call
are written after a dot: `name.<Type>(...)`. In types, such as `List<Int>`, no dot is needed.

Wrong:

```wolf wrong
module main

functions {
    fn empty<T>() -> List<T> {
        []
    }

    fn main() {
        let items = empty<Int>()
        print(items.len().to_string())
    }
}
```

Fixed:

```wolf fixed
module main

functions {
    fn empty<T>() -> List<T> {
        []
    }

    fn main() {
        let items = empty.<Int>()
        print(items.len().to_string())
    }
}
```
