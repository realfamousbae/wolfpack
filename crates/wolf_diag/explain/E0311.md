# E0311: type arguments without a dot in an expression

Type arguments in an expression are written after a dot, `f.<Int>(x)`, so that `<` is never read
as a comparison.

Wrong:

```wolf
module main

functions {
    fn first<T: Copyable>(items: List<T>) -> T { items[0].copy() }

    fn main() {
        print(first<Int>([1, 2]).to_string())
    }
}
```

Fixed:

```wolf
module main

functions {
    fn first<T: Copyable>(items: List<T>) -> T { items[0].copy() }

    fn main() {
        print(first.<Int>([1, 2]).to_string())
    }
}
```
